# Готов к проверке

Бот и мини-приложение в MAX, которые помогают владельцу кафе или салона красоты подготовиться к проверке **до того**, как придёт инспектор.

Хакатон MAX, трек «Эффективный бизнес».

**Попробовать:** бот в MAX — [https://max.ru/t194_hakaton_max_bot](https://max.ru/t194_hakaton_max_bot) (@t194_hakaton_max_bot) · мини-приложение открывается из бота кнопкой «Открыть приложение» (адрес `https://gotov-k-proverke-caxar010123.amvera.io`).

## Зачем мы это сделали

Когда у тебя маленькое кафе на 30 посадочных мест, ты одновременно директор, бухгалтер, закупщик и иногда повар. Требований к бизнесу много: СанПиН, пожарная безопасность, трудовой кодекс, касса, защита прав потребителей. Они разбросаны по десяткам документов, и понять, что из этого относится именно к тебе, без юриста сложно.

В итоге про нарушение узнают на проверке — вместе со штрафом. А большинство типовых нарушений (нет журнала температур, просрочена медкнижка, заставлен запасный выход) исправляются за день и почти бесплатно, если знать о них заранее.

«Готов к проверке» за 5–7 минут показывает:

- какие требования касаются именно вашего бизнеса — с учётом вида деятельности, ИП или ООО, есть ли сотрудники;
- где вы им не соответствуете и сколько за это могут оштрафовать;
- что исправить в первую очередь и к какому сроку;
- и напоминает о сроках в MAX, пока всё не будет исправлено.

## Как это работает для пользователя

1. Открываете бота в MAX и нажимаете «Начать самопроверку».
2. Отвечаете на 3–4 вопроса о бизнесе.
3. Бот подбирает требования под ваш профиль (13–19 пунктов) и предлагает пройти их прямо в чате или в мини-приложении.
4. На каждый пункт отвечаете «Да», «Нет» или «Не знаю». По кнопке можно посмотреть, что именно требуется, на основании какого документа, кто проверяет и какой штраф.
5. В конце получаете отчёт: процент готовности, возможные штрафы и план исправлений со сроками.
6. Бот напоминает о сроках. Исправили пункт — отмечаете, и готовность растёт.

Прогресс общий: можно начать в чате в дороге, а закончить в мини-приложении с компьютера. В мини-приложении к каждому пункту можно прикрепить фото и комментарий — удобно собрать «папку для инспектора».

## Из чего состоит

```
MAX (чат)                    MAX (мини-приложение, HTTPS)
    │                              │  React + MAX UI + MAX Bridge
    │ long polling                 │  запросы с подписью initData
    ▼                              ▼
┌──────────────────────────────────────────────┐
│ Node.js-сервис (один контейнер)              │
│  bot/          сценарий чат-бота             │
│  api.js        API мини-приложения + статика │
│  auth.js       проверка подписи initData     │
│  service.js    общая логика для бота и API   │
│  assessment.js расчёт готовности и штрафов   │
│  reminders.js  напоминания о сроках          │
│  catalog.js    справочник требований         │
└──────────────────────────────────────────────┘
                     │
      SQLite + фото в /data   ·   data/checklists.json
```

- `server/` — Node.js 24, официальный SDK `@maxhub/max-bot-api`, Express 5, встроенный `node:sqlite`.
- `web/` — React 19, библиотека `@maxhub/max-ui`, MAX Bridge, сборка Vite.
- Бот, API и мини-приложение работают в одном контейнере — для MVP этого достаточно, и так проще разворачивать.

Главное архитектурное решение: логика не знает ничего о конкретных требованиях. Всё содержимое — в `server/data/checklists.json`. Чтобы добавить новую отрасль (например, магазин или автосервис), достаточно дописать туда блок требований, код трогать не нужно.

## Запуск

Одной командой через Docker:

```bash
cp .env.example .env     # и впишите BOT_TOKEN
docker compose up -d --build
```

Проверить, что всё поднялось: `curl http://localhost:8080/api/health` должен вернуть `{"ok":true,"bot":true}`.

Мини-приложению MAX нужен HTTPS. Варианты:

- **На сервере с публичным IP** — встроенный Caddy сам получит сертификат: укажите `DOMAIN` в `.env` и запустите `docker compose --profile https up -d --build`. Для сервера на Ubuntu есть скрипт `setup-server.sh`, который делает всё сам.
- **Для быстрой демонстрации** — туннель Cloudflare: `docker compose --profile tunnel up -d`.
- **На Amvera** (так работает наша демо-версия) — в репозитории есть `amvera.yml`. Подключаете репозиторий, задаёте переменные `BOT_TOKEN` и `MINIAPP_URL`, включаете бесплатный домен — и всё.

Адрес мини-приложения нужно указать и в `MINIAPP_URL`, и привязать к боту в MAX (в настройках бота на платформе MAX для партнёров; для ботов, выданных на хакатоне, — через форму организаторов). Без него бот всё равно полностью работает в чате, просто не показывает кнопку «Открыть приложение».

На Windows без Docker можно запустить двойным щелчком по `start-bot.cmd` (нужен Node.js 22+).

## Настройки (.env)

| Переменная | Нужна? | По умолчанию | Что это |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен бота MAX |
| `MINIAPP_URL` | нет | — | HTTPS-адрес мини-приложения, включает кнопку «Открыть приложение» |
| `BOT_USERNAME` | нет | берётся из `/me` | ник бота для кнопки мини-приложения |
| `BOT_ENABLED` | нет | `true` | `false` — только API и мини-приложение, без бота |
| `REMINDER_DEMO_SECONDS` | нет | `0` | для демо: первое напоминание через N секунд после отчёта (в `.env.example` стоит 60). `0` — за сутки до срока |
| `DOMAIN` | нет | — | домен для HTTPS через Caddy |
| `HOST_PORT` | нет | `8080` | порт на хосте |
| `DEV_AUTH` | нет | `false` | только для разработки: вход в мини-приложение вне MAX через заголовок `X-Dev-User` |
| `INIT_DATA_MAX_AGE` | нет | `86400` | сколько секунд действительна подпись initData |
| `REMINDER_INTERVAL_MS` | нет | `30000` | как часто проверять напоминания |

`PORT`, `DATA_DIR`, `WEB_DIR` и путь к сертификатам уже заданы в Dockerfile.

## Порты

- `8080` — API (`/api/*`) и мини-приложение.
- `80`, `443` — только с профилем `https` (Caddy).
- `5173` — только при разработке фронтенда (`npm run dev` в `web/`).

## Зависимости

Версии зафиксированы в `server/package-lock.json` и `web/package-lock.json`.

- Сервер: `@maxhub/max-bot-api@0.3.1`, `express@5.2.1`. База — встроенный в Node.js модуль `node:sqlite`, ничего компилировать не нужно.
- Мини-приложение: `react@19.2.8`, `@maxhub/max-ui@0.5.0`, сборка `vite@8.3.1`.
- Образ: `node:24-alpine`. Сборка занимает 1–3 минуты.

## Внешние сервисы

| Сервис | Зачем |
|---|---|
| MAX Bot API (`platform-api.max.ru`) | получать сообщения и отвечать |
| MAX Bridge (`st.max.ru/js/max-web-app.js`) | узнать пользователя в мини-приложении; подпись `initData` проверяется на сервере |
| Caddy / Cloudflare Tunnel / Amvera | HTTPS для мини-приложения (что-то одно) |

Две вещи, на которых мы споткнулись и которые стоит знать:

1. MAX Bot API отвечает только из российской сети. С включённым VPN бот не подключится.
2. Сертификат `platform-api.max.ru` выпущен HARICA, и Node.js по умолчанию не может достроить цепочку. Поэтому в `certs/max-ca-bundle.pem` лежат нужные корневые и промежуточные сертификаты (плюс сертификаты Минцифры), а в Docker они подключаются через `NODE_EXTRA_CA_CERTS`.

## Данные

**Что реальное, а что нет.** Справочник требований (`server/data/checklists.json`) мы собрали сами по открытым нормативным актам: СанПиН, Правила противопожарного режима, Трудовой кодекс, КоАП РФ и другие — полный список есть в самом файле и в боте по команде `/sources`. Это **демонстрационный набор**: 2 вида деятельности, 33 требования, суммы штрафов ориентировочные, юрист его не проверял. К ФГИС ЕРКНМ и Порталу КНД мы в MVP не подключались. Пользователь видит это предупреждение и в боте, и в приложении.

**Что хранится.** SQLite в `/data/app.db`: пользователи, профили бизнеса, проверки (со снимком профиля и списка требований на момент прохождения), ответы, задачи плана и незавершённые диалоги в чате. Фото — в `/data/uploads/<user_id>/`, только JPEG/PNG/WebP до 5 МБ, телефон сжимает их до 1280 px перед отправкой.

**Кто что видит.** Каждый запрос мини-приложения подписан MAX (`initData`), сервер проверяет подпись токеном бота и срок её действия. Пользователь видит только свои проверки, задачи и фото — это проверяется в каждом методе.

**Как считается готовность.** У каждого требования есть вес: высокая важность — 3, средняя — 2, низкая — 1. Готовность — это доля веса пунктов с ответом «Да». Статус «Готов к проверке» — от 85 % и ни одного открытого критичного нарушения; 60–84 % — «Есть риски»; ниже — «Высокий риск штрафов». «Не знаю» считаем риском: лучше перепроверить.

## Тестовые данные

Отдельно загружать ничего не надо — справочник уже внутри образа. Удобные профили для проверки:

| Профиль | Сколько требований |
|---|---|
| Кафе, ИП, без сотрудников, без алкоголя | 13 |
| Кафе, ООО, с сотрудниками, с алкоголем | 19 |
| Салон красоты, ООО, с сотрудниками, с медкосметологией | 14 |

Чтобы не ждать напоминания сутки, поставьте `REMINDER_DEMO_SECONDS=60`.

## Как проверить основной сценарий

1. Откройте бота в MAX и нажмите «Начать» (или `/start`).
2. «Начать самопроверку» → «ИП» → «Кафе, столовая, ресторан» → «Есть сотрудники» → «Нет» (про алкоголь).
3. Бот напишет, что подобрал 18 требований. Выберите «Пройти здесь, в чате».
4. На первом вопросе нажмите «Требование и штраф» — придёт карточка с нормой и суммой штрафа.
5. Ответьте на вопросы: пару раз «Нет», один-два раза «Не знаю», остальное «Да».
6. Придёт отчёт. Откройте «План исправлений» и нажмите «✅ 1» — пункт отметится, список обновится.
7. Примерно через минуту придёт напоминание с кнопками «Исправлено» и «+3 дня».
8. Если подключено мини-приложение: «Открыть приложение» → на главной видно готовность и план. Там же можно пройти проверку заново, открыть подробности пункта и прикрепить фото. После «Получить отчёт» отчёт придёт и в чат.

## Тесты

```bash
cd server && npm ci && npm test
```

Проверяем подбор требований под профиль, расчёт готовности и штрафов, планирование напоминаний, подпись initData (подделку, чужой токен, просроченную подпись) и весь сценарий через API: профиль → проверка → ответы → отчёт → задачи, включая то, что чужой пользователь не видит ваши данные, а повторное завершение проверки ничего не ломает.

## Что пока не умеем

- Справочник демонстрационный: 2 вида деятельности, 33 требования, без юридической проверки. Штрафы ориентировочные.
- Нет интеграции с ФГИС ЕРКНМ и Порталом КНД — ни проверочных листов оттуда, ни плана проверок.
- Не учитываем региональные требования и категорию риска объекта.
- Один экземпляр сервиса (SQLite, long polling). Для масштаба нужны PostgreSQL и webhook.
- Фото хранятся на томе сервиса, резервные копии — средствами хостинга.
- Кнопка мини-приложения появляется, только если задан `MINIAPP_URL` и адрес прописан в настройках бота в MAX.
- MAX Bot API доступен только из российской сети.

## Остановить и запустить снова

```bash
docker compose down            # остановить (данные останутся в томе app-data)
docker compose up -d           # запустить снова
docker compose up -d --build   # пересобрать после изменений
docker compose logs -f app     # смотреть логи
docker compose down -v         # остановить и удалить все данные
```

На Amvera — кнопки «Пересобрать» и «Перезапустить» в карточке проекта.
