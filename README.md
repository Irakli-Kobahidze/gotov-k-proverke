# «Готов к проверке» — самопроверка малого бизнеса перед проверками в MAX

Чат-бот с мини-приложением для мессенджера MAX. Помогает владельцу кафе или салона красоты
**до прихода инспектора** понять, каким обязательным требованиям Роспотребнадзора, МЧС,
трудовой инспекции и ФНС он не соответствует, сколько это может стоить и что исправить в первую очередь.

Трек хакатона: **«Эффективный бизнес»**, направление «Контроль и надзор без лишней нагрузки».

## Назначение

| | |
|---|---|
| **Пользователь** | Владелец/управляющий микробизнеса (ИП или ООО, 0–15 сотрудников) в общепите и бьюти-сфере |
| **Проблема** | Требования разбросаны по десяткам нормативных актов; непонятно, что относится именно к нему. Итог — штраф за типовое нарушение или оплата консультанта |
| **Результат** | За 5–7 минут: персональный чек-лист, % готовности, сумма возможных штрафов, план исправлений со сроками и напоминания в чат |

## Основной пользовательский сценарий

1. Пользователь открывает бота в MAX → «Начать самопроверку».
2. Отвечает на 3–4 вопроса профиля: форма бизнеса (ИП/ООО), вид деятельности, есть ли сотрудники, уточнение (алкоголь / медкосметология).
3. Бот подбирает применимые требования (13–19 из справочника) и предлагает пройти их **в чате** или **в мини-приложении**.
4. На каждый пункт — «Да / Нет / Не знаю»; по кнопке видно требование, основание (норма), контролирующий орган, статью КоАП и штраф, способ исправления. В мини-приложении можно прикрепить фото-подтверждение и комментарий.
5. После последнего ответа — отчёт: % готовности, уровень риска, возможные штрафы для выбранной формы бизнеса, нарушения по приоритету.
6. Автоматически формируется план исправлений со сроками; бот напоминает о сроках, пользователь отмечает «Исправлено» или переносит срок — готовность пересчитывается.

Прогресс общий для чата и мини-приложения: можно начать в чате и продолжить в приложении.

## Состав и архитектура

```
 MAX (мобильный / веб-клиент)
   │  чат                                 │  мини-приложение (WebView, HTTPS)
   ▼                                      ▼
 MAX Bot API  ◄── long polling ──┐   React + MAX UI + MAX Bridge (initData)
 platform-api.max.ru             │        │  /api/*  (заголовок X-Max-Init-Data)
                                 │        ▼
                        ┌────────┴──────────────────────────────┐
                        │  Node.js-сервис (один контейнер)       │
                        │  ├─ bot/        сценарий чат-бота      │
                        │  ├─ api.js      REST API + статика SPA │
                        │  ├─ auth.js     проверка подписи       │
                        │  │              initData (HMAC-SHA256) │
                        │  ├─ service.js  бизнес-логика (общая)  │
                        │  ├─ assessment  расчёт готовности,     │
                        │  │              штрафов, плана         │
                        │  ├─ reminders   планировщик напоминаний│
                        │  └─ catalog     справочник требований  │
                        └──────────┬────────────────────────────┘
                                   ▼
                     SQLite (/data/app.db) + фото (/data/uploads)
                     data/checklists.json — справочник требований
```

* **server/** — Node.js 24, `@maxhub/max-bot-api` (официальный SDK MAX), Express 5, встроенный `node:sqlite`.
* **web/** — React 19 + `@maxhub/max-ui` (официальная библиотека компонентов MAX) + MAX Bridge, сборка Vite.
* Один Docker-образ: сервер отдаёт и API, и собранное мини-приложение.

Ядро продукта (сценарий, расчёт, UI) не зависит от содержимого справочника. Новая отрасль или
вид контроля подключается добавлением блока в `server/data/checklists.json` без изменения кода.

## Запуск одной командой

```bash
cp .env.example .env        # впишите BOT_TOKEN (и MINIAPP_URL, если подключаете мини-приложение)
docker compose up -d --build
```

Проверка: `curl http://localhost:8080/api/health` → `{"ok":true,"bot":true}`.

### HTTPS для мини-приложения

MAX открывает мини-приложения только по HTTPS. Варианты:

* сервер с доменом и TLS (nginx/Caddy) → проксировать на порт 8080;
* для демонстрации — встроенный туннель Cloudflare:
  ```bash
  docker compose --profile tunnel up -d --build
  docker compose logs tunnel | grep trycloudflare.com
  ```
  Полученный адрес `https://….trycloudflare.com` укажите в настройках мини-приложения бота
  на платформе MAX для партнёров и в `MINIAPP_URL`, затем `docker compose up -d`.

Без `MINIAPP_URL` бот работает полностью (весь сценарий в чате), кнопка «Открыть приложение» скрыта.

## Параметры окружения

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `BOT_TOKEN` | да | — | Токен чат-бота MAX |
| `MINIAPP_URL` | нет | — | Публичный HTTPS-адрес мини-приложения; включает кнопки `open_app` |
| `BOT_USERNAME` | нет | из `/me` | Ник бота для кнопки открытия мини-приложения |
| `BOT_ENABLED` | нет | `true` | `false` — только API и мини-приложение (без бота) |
| `HOST_PORT` | нет | `8080` | Порт на хосте (compose) |
| `REMINDER_DEMO_SECONDS` | нет | `0` (в `.env.example` — `60`) | Первое напоминание через N секунд после отчёта — для демонстрации. `0` — за сутки до срока |
| `DEV_AUTH` | нет | `false` | Только для разработки вне MAX: разрешает заголовок `X-Dev-User` |
| `INIT_DATA_MAX_AGE` | нет | `86400` | Срок действия подписи initData, сек |
| `REMINDER_INTERVAL_MS` | нет | `30000` | Период проверки напоминаний |
| `PORT`, `DATA_DIR`, `WEB_DIR` | нет | `8080`, `/data`, `/app/web` | Задаются в Dockerfile |

| Порт | Назначение |
|---|---|

## Зависимости

Версии зафиксированы в `server/package-lock.json` и `web/package-lock.json`.

* Сервер: `@maxhub/max-bot-api@0.3.1`, `express@5.2.1`; БД — встроенный модуль Node.js `node:sqlite`.
* Мини-приложение: `react@19.2.8`, `react-dom@19.2.8`, `@maxhub/max-ui@0.5.0`; сборка — `vite@8.3.1`, `@vitejs/plugin-react@6.1.1`.
* Базовый образ: `node:24-alpine`. Сборка образа — около 1–2 минут.

## Внешние сервисы и интеграции

| Сервис | Назначение | Как используется |
|---|---|---|
| MAX Bot API (`platform-api.max.ru`) | Получение обновлений и отправка сообщений | Long polling через официальный SDK |
| MAX Bridge (`st.max.ru/js/max-web-app.js`) | Данные пользователя в мини-приложении | `initData` проверяется на сервере по HMAC-SHA256 |
| Cloudflare Tunnel (необязательно) | HTTPS-адрес для демонстрации | Профиль `tunnel` в compose |

> ⚠️ MAX Bot API доступен только из российской сети. Запускайте сервис на сервере/компьютере с российским IP (без VPN).

**Модельные данные.** Реальная интеграция с ФГИС ЕРКНМ / Порталом КНД (проверочные листы, план проверок)
в MVP **не подключена**. Справочник требований `server/data/checklists.json` — демонстрационный набор,
составленный командой по открытым нормативным актам (перечень источников — в самом файле и по команде `/sources`).
Суммы штрафов ориентировочные. Это явно показано пользователю в боте и в приложении.

## Работа с данными

* **Справочник** (`server/data/checklists.json`): виды деятельности → требования. Для каждого: вопрос, текст требования,
  основание, контролирующий орган, критичность (`high/medium/low`), статья КоАП и диапазон штрафа для ИП и организаций,
  способ исправления, срок исправления, условия применимости (`when`: наличие сотрудников, флаги). Проверяется при старте.
* **БД SQLite** (`/data/app.db`, том `app-data`): `users`, `profiles`, `checks` (снимок профиля и списка требований),
  `answers`, `tasks` (план и напоминания), `chat_state` (незавершённый диалог в чате).
* **Фото** — `/data/uploads/<user_id>/`, только JPEG/PNG/WebP до 5 МБ, сжимаются на устройстве до 1280 px.
  Доступ к фото — только владельцу через API.
* **Авторизация**: каждый запрос мини-приложения несёт подписанный `initData`; сервер проверяет подпись токеном бота
  и срок действия. Пользователь видит только свои проверки и задачи (проверка владельца на каждом методе).
* **Расчёт готовности**: вес требования по критичности (3/2/1); готовность = доля веса пунктов «Да».
  «Готов к проверке» — ≥ 85 % и нет открытых критичных нарушений; 60–84 % — «Есть риски»; ниже — «Высокий риск».
  «Не знаю» считается риском. Штрафы суммируются по нарушениям для выбранной формы бизнеса.

## Тестовые данные

Отдельной загрузки не требуется — справочник встроен в образ. Для проверки подойдут профили:

| Профиль | Требований |
|---|---|
| Кафе · ИП · без сотрудников · без алкоголя | 13 |
| Кафе · ООО · с сотрудниками · с алкоголем | 19 |
| Салон · ООО · с сотрудниками · медкосметология | 14 |

Чтобы быстро увидеть напоминание, задайте `REMINDER_DEMO_SECONDS=60`: первое напоминание придёт через минуту после отчёта.

## Пошаговый сценарий проверки

1. Откройте бота в MAX, нажмите «Начать» (или отправьте `/start`).
2. «🚀 Начать самопроверку» → «ИП» → «🍽 Кафе, столовая, ресторан» → «👥 Есть сотрудники» → «Нет» (алкоголь).
3. Бот сообщает: «Подобрал 18 требований…». Нажмите «💬 Пройти здесь, в чате».
4. На первый вопрос нажмите «📖 Требование и штраф» — придёт карточка с нормой и штрафом.
5. Ответьте на вопросы (например, 3–4 раза «❌ Нет», пару «❓ Не знаю», остальные «✅ Да»).
6. Получите отчёт → «📋 План исправлений» → нажмите «✅ 1» — пункт отмечен, список обновится.
7. Через минуту (при `REMINDER_DEMO_SECONDS=60`) придёт напоминание с кнопками «✅ Исправлено» / «⏳ +3 дня».
8. Если подключено мини-приложение: «📱 Открыть приложение» → на главной видны готовность, отчёт, план.
   «Пройти проверку заново» → ответы кнопками, «Что проверит инспектор и какой штраф?», «📷 Прикрепить фото».
   После «Получить отчёт» отчёт дублируется в чат.

## Примеры ожидаемого поведения

| Действие | Ожидаемый результат |
|---|---|
| Профиль «Кафе, ИП, без сотрудников» | Требования о медкнижках, трудовых договорах, охране труда не показываются |
| Ответ «Нет» на «Эвакуационные выходы свободны…» (ИП) | В отчёте — высокая критичность, КоАП 20.4 ч. 1, до 60 000 ₽, срок 3 дня |
| Все ответы «Да» | Готовность 100 %, «Готов к проверке», план пуст |
| «✅ Исправлено» по задаче | Готовность «с учётом исправлений» растёт, напоминания по задаче прекращаются |
| Повторное нажатие старой кнопки ответа после завершения | Сообщение «Эта проверка уже завершена», данные не меняются |
| Произвольный текст в чат | Подсказка с кнопками «Продолжить проверку» / «Меню» |
| Запрос к API без подписи MAX | `401 {"error":"unauthorized"}`; в браузере — экран «Откройте приложение из MAX» |
| Потеря сети в мини-приложении | Сообщение об ошибке, повторить действие можно без перезапуска |

## Тесты

```bash
cd server && npm ci && npm test
```

Покрыты: фильтрация справочника по профилю, расчёт готовности и штрафов, планирование напоминаний,
проверка подписи initData (подделка, чужой токен, истёкший срок), сквозной сценарий API
(профиль → проверка → ответы → отчёт → задачи, изоляция пользователей, идемпотентность завершения).

## Локальная разработка без Docker

```bash
cd web && npm ci && npm run build          # собрать мини-приложение
cd ../server && npm ci
BOT_TOKEN=... npm start                    # бот + API на :8080
# UI вне MAX: BOT_ENABLED=false DEV_AUTH=true npm start → http://localhost:8080/?dev=1
```

## Известные ограничения

* Справочник требований — демонстрационный (2 вида деятельности, 33 требования), без юридической верификации;
  суммы штрафов ориентировочные. Интеграция с ФГИС ЕРКНМ / Порталом КНД не реализована.
* Сервис не учитывает региональные требования и не определяет категорию риска объекта контроля.
* Один экземпляр сервиса (SQLite, long polling). Для горизонтального масштабирования нужны PostgreSQL и webhook.
* Фото хранятся локально на томе; резервное копирование — средствами хостинга.
* Кнопка `open_app` появляется только при заданном `MINIAPP_URL`; если платформа её отклонит, бот продолжит работу без неё.
* MAX Bot API доступен только из российской сети.

## Развёртывание на сервере (Ubuntu)

```bash
apt update && apt install -y git
git clone <адрес репозитория> app && cd app
bash setup-server.sh
```

Скрипт установит Docker, спросит токен бота, создаст `.env`, выпустит HTTPS-сертификат для адреса
`<ip-с-дефисами>.sslip.io` (Caddy + Let's Encrypt) и запустит бота с мини-приложением.
Этот адрес нужно указать как ссылку мини-приложения в настройках бота на платформе MAX.

Локально на Windows без Docker: двойной щелчок по `start-bot.cmd` (нужен Node.js 22+, без VPN).

## Остановка и повторный запуск

```bash
docker compose down            # остановить (данные сохраняются в томе app-data)
docker compose up -d           # запустить снова
docker compose up -d --build   # пересобрать после изменений
docker compose logs -f app     # логи
docker compose down -v         # остановить и удалить все данные
```
